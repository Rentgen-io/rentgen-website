2. Compare environments

Regression out of the box

A new build landed in staging. Did it change how your API handles bad input?

Import a working cURL, map the fields, and click Generate and Run. Select the finished run with Select for Compare to keep it as your baseline. Then switch to other environment and run again.

Click Compare with Selected to see what changed. Rentgen uses field context to filter expected differences and highlight potential regressions. If the baseline rejected an input and the new build accepts it, you have a concrete change to investigate, even with zero regression tests written.

3. Check LLM replies

LLM pre-evaluation

You changed your support bot’s instructions. Does it still give customers the right answer?

Import the cURL for your LLM endpoint and open Pre-evaluation. Add a question a customer might ask, such as “How do I reset my password?” Then define what the reply should contain and what it should leave out.

For this question, require “Forgot password” and exclude “Send us your password.” Click Run, see which checks passed, and open a failure to read the actual reply. You get specific evidence to review before shipping the change, based on the checks you defined.
